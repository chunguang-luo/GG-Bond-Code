## 启动链路

```
cli.py (Click entry)
  │
  ├─ 快速路径: --version → 直接打印返回
  ├─ 快速路径: --print → 非交互模式
  │
  └─ 正常路径:
      → init()        # 配置、认证、API 预连接
      → setup()       # 工作目录、会话状态、Store ↔ Settings 桥接
      │
      ├─ --ink off    → repl.launch()      # Rich REPL
      ├─ --ink auto   → 尝试 Ink，失败回退 Rich
      └─ --ink on     → IPCBridge + Ink   # 双进程模式
```

```
│                                    │◄────────────────►│                      │
│  IPCBridge                          │                   │  App (React + Ink)   │
│  ├─ QueryRunner                     │                   │  ├─ WelcomeScreen    │

```

## 上下文压缩架构

```
Token 用量低 ──→ NONE（无操作）
                │
接近阈值 ──────→ MICRO（清除旧工具结果，无模型调用）
                │   └─ 无可清除 → 升级为 FULL
达到阈值 ──────→ FULL（模型摘要 + 近期消息保留 + 文件重新注入）
                │   └─ 断路器开启 → 降级为 MICRO
超出上限 ──────→ BLOCKING（拒绝新查询，需手动 /compact）
```

### 压缩策略细节

| 级别 | 机制 | 成本 | 信息损失 |
|------|------|------|---------|
| MICRO | 清除旧 tool_result，保留最近 3 条 | 几乎为零 | 低 |
| FULL | 模型生成 9 维结构化摘要 + 保留 5~20 条近期消息 | 一次 API 调用 | 中 |
| BLOCKING | 拒绝新查询 | 无 | — |

### FULL Compact 流程

1. 断路器检查（3 次连续失败停止）
2. 构建压缩提示词（对话历史序列化，tool_result 截断 500 字符）
3. 流式生成摘要（CoT `<analysis>` + 正式 `<summary>`）
4. 格式化摘要（剥离 `<analysis>`，提取 `<summary>`）
5. 重建消息列表：`[summary_message] + [recent_messages]`
6. 修复 tool reference（移除孤立的 tool_use/tool_result 对）
7. 重新注入最近访问的文件内容（最多 5 个文件，10K token 预算）

## 命令系统架构

```
用户输入 "/compact"
       │
       ▼
  CommandDispatcher.parse()
       │
       ├─ 精确匹配 → 执行 handler
       │
       └─ 未匹配 → 计算编辑距离，提示相似命令
                    "Did you mean /compact?"
```

- **CommandRegistry**：注册命令（名称 + 别名 + 描述 + handler）
- **CommandDispatcher**：解析输入 → 查找命令 → 执行 → 结果格式化
- **LocalCommand**：本地执行的命令（如 `/clear`、`/compact`）
- **PromptCommand**：转换为 prompt 的命令（Phase 2，如 `/doc`）
- **Tab 补全**：输入 `/` 时列出所有可用命令
- **相似命令提示**：输入错误命令时，基于编辑距离推荐

## 状态管理架构

```
┌──────────────────────────────────────────────────────────┐
│                    setup() 初始化                          │
│  reset_store(on_change=_on_store_change)                 │
│  Store ← Settings (加载默认值)                            │
│  Store → Settings (onChange 自动同步持久化 key)            │
└──────────────────────┬───────────────────────────────────┘
                       │
          ┌────────────┴────────────┐
          │                         │
   create_store_context()    create_subagent_context()
   (主循环)                   (子 Agent)
          │                         │
   get_state → Store.get     get_state → Store.get (只读)
   set_state → Store.set     set_state → no-op (隔离)
   set_state_for_tasks       set_state_for_tasks → 穿透到根 Store
          │                         │
          ▼                         ▼
    QueryRunner               子 Agent QueryRunner
```

核心原则：
- **单一状态源**：Store 是唯一的运行时状态源，Settings 是持久化层
- **集中式副作用**：onChange 回调统一处理持久化、通知等副作用
- **隔离 + 选择性穿透**：子 Agent 默认隔离，任务注册始终穿透到根 Store

## 关键设计决策

1. **Click 而非 Typer**：Typer 底层是 Click，但 Click 更灵活，对子命令和 pre-action hook 支持更好
2. **双 UI 模式**：Rich REPL 零依赖开箱即用，Ink 前端提供更丰富的交互体验，通过 `--ink` 选项切换
3. **Unix Domain Socket IPC**：比 stdin/stdout pipe 更可靠，支持双向通信，无需端口分配
4. **asyncio 全异步**：API 调用、工具执行、流式输出、IPC 通信都需要异步
5. **Pydantic 做 Tool schema**：同时用于参数验证和生成 JSON Schema 给 API
6. **三级上下文压缩**：MICRO（零成本）→ FULL（API 调用）→ BLOCKING（保护），断路器防止无限重试
7. **静态/动态 Prompt 分割**：System Prompt 分为静态部分（可缓存）和动态部分（每次变化），优化 Prompt Cache 命中率
8. **ToolUseContext 解耦**：QueryRunner 通过 ToolUseContext 间接访问 Store，支持子 Agent 隔离和任务穿透
9. **Setting 配置**：JSON 格式，`~/.nextcode/.settings.json`（全局）+ `.nextcode/.settings.json`（项目级）
