# 对话循环实现详细文档

## 目标

实现 `query.py` → `api/` 对话循环，完成以下核心流程：

```
用户输入 → 组装消息 + System Prompt → 调用 API（流式）
→ 模型返回 tool_use → 执行工具 → 结果回传 → 模型继续/结束
```

### 当前数据链路

```
cli.py main()
  └→ main.py cli() (Click)
       ├→ init()          # 加载配置 + 认证 + API 预连接
       └→ setup(cwd, model) # 设置工作目录 + 初始化 Store
            ├→ 交互模式: REPL.run()
            │    └→ _run_query(input)
            │         └→ QueryRunner.run(input)
            │              ├→ stream_message()   # API 流式调用
            │              ├→ 工具执行
            │              └→ Store 持久化
            └→ 非交互模式: QueryRunner.run(stdin)
```

### 现有问题清单

#### 1. `query.py` — Anthropic 多工具结果合并错误

```python
# 当前代码：每个 tool_use 单独生成一条 user 消息
for tb in tool_use_blocks:
    messages.append({
        "role": "user",
        "content": [{"type": "tool_result", "tool_use_id": tb["id"], ...}],
    })
```

**问题**：Anthropic API 要求一次 API 调用产生的所有 tool_result 必须放在**同一个** `role: "user"` 消息的 content 数组中，不能拆成多条消息。当前写法会导致 400 错误。

**修复**：收集所有 tool_result 后一次性追加。

#### 2. `query.py` — 权限决策 ASK 时直接跳过交互

```python
# 当前代码：ASK 和 DENY 同等处理，没有交互确认
if decision == PermissionDecision.DENY:
    result = ToolResult(output="Permission denied", error=True)
else:
    result = await self._execute_tool(tb["name"], tb["input"])
```

**问题**：`PermissionDecision.ASK` 应该触发交互式确认，但当前直接执行了工具。

**修复**：QueryRunner 需要一个回调机制，让 REPL 层处理交互确认。

#### 3. `query.py` — Store 每次调用都创建新实例

```python
# 当前代码
store = Store()  # 每次调用都创建（虽然 Store 是单例，但语义不清晰）
```

**问题**：Store() 返回单例，但每次 `run()` 内部都 `Store()` 取 messages，容易混淆。

**修复**：在 `__init__` 中获取 store 实例，复用。

#### 4. `api/client.py` — Anthropic 流式缺少 tool_use 实时事件

```python
# 当前代码：tool_use 在 message_stop 之后才批量 yield
async for event in stream:
    if event.type == "content_block_delta":
        ...
    elif event.type == "message_stop":
        break
# 流结束后才获取 tool_use blocks
message = await stream.get_final_message()
for block in message.content:
    if block.type == "tool_use":
        yield {"type": "tool_use", ...}
```

**问题**：用户在流式输出时看不到工具调用的实时进度（工具名、参数增量）。

**修复**：处理 `content_block_start` 和 `input_json_delta` 事件，实时 yield 工具调用进度。

#### 5. `api/client.py` — 缺少错误重试和超时

**问题**：API 调用失败时没有重试机制，也没有连接/读取超时配置。

**修复**：添加指数退避重试 + httpx 超时配置。

#### 6. `repl.py` — thinking 内容完全不展示

```python
elif event.type == "thinking":
    pass  # 直接跳过
```

**问题**：DeepSeek reasoner 模型的思维链完全不可见，用户无法了解推理过程。

**修复**：用 Rich 折叠面板展示 thinking 内容。

#### 7. `repl.py` — 流式文本输出体验差

```python
self.console.print(event.content, end="", highlight=False)
```

**问题**：逐 token 输出时，Rich 的 `console.print` 每次调用都有开销，且无法正确处理 Markdown 格式（需要完整内容才能解析）。

**修复**：流式阶段逐 token 输出纯文本，结束后用 Rich Markdown 重新渲染最终结果。

#### 8. `tools/base.py` — 缺少安全执行包装

**问题**：工具执行没有超时保护，异常直接抛出到 query 层。

**修复**：添加 `execute_safe()` 方法，统一超时和异常捕获。

## 实现计划

### Phase 1: 修复 `api/client.py` — 完善流式事件 + 错误处理

**改动范围**：`api/client.py`

**具体内容**：

1. **Anthropic 流式实时 tool_use 事件**
   - 处理 `content_block_start` 事件：yield `tool_start`（工具名）
   - 处理 `input_json_delta` 事件：yield `tool_input_delta`（参数增量）
   - 处理 `content_block_stop` 事件：yield `tool_end`（完整参数）
   - 保留 `get_final_message()` 作为兜底

2. **添加重试机制**
   - 对 429 (rate limit) 和 5xx 错误做指数退避重试（最多 3 次）
   - 对 4xx 错误直接抛出，不重试

3. **添加超时配置**
   - 连接超时 10s，读取超时 120s
   - 通过 httpx.Timeout 配置

**新增事件类型**：

```python
# Anthropic 流式新增事件
{"type": "tool_start", "name": "Bash", "id": "toolu_xxx"}
{"type": "tool_input_delta", "delta": '{"command": "ls'}
{"type": "tool_end", "id": "toolu_xxx", "name": "Bash", "input": {"command": "ls"}}
```

### Phase 2: 修复 `query.py` — 核心循环 bug 修复 + 权限回调

**改动范围**：`query.py`

**具体内容**：

1. **修复 Anthropic 多工具结果合并**
   ```python

   tool_results_content = []
   for tb in tool_use_blocks:
       result = await self._execute_tool_with_permission(tb)
   ```

2. **添加权限确认回调**
   ```python
   class QueryRunner:
       def __init__(self, ..., permission_callback: Callable | None = None):
           self._permission_callback = permission_callback

       async def _check_permission(self, tool_name, params):
           decision = self.permissions.check(tool_name, params)
           if decision == PermissionDecision.ASK and self._permission_callback:
               decision = await self._permission_callback(tool_name, params)
           return decision
   ```

3. **处理新的流式事件**
   - `tool_start`：yield 事件通知 REPL 显示工具开始
   - `tool_input_delta`：可选的实时参数展示
   - `tool_end`：替代原来的 `tool_use` 事件

4. **Store 复用优化**

**具体内容**：

1. **添加 `execute_safe()` 方法**
   ```python
   async def execute_safe(self, params: dict) -> ToolResult:
       try:
           return await asyncio.wait_for(
               self.execute(params),
               timeout=self.get_timeout()
           )
       except asyncio.TimeoutError:
           return ToolResult(output="Tool execution timed out", error=True)
       except Exception as e:
           return ToolResult(output=f"Tool error: {e}", error=True)

   def get_timeout(self) -> float:
       return 120.0
   ```

## 风险点

1. **Anthropic 流式事件格式**：`content_block_start` / `input_json_delta` 的事件结构需要实测验证
2. **input_json_delta 增量拼接**：JSON 片段拼接可能有边界问题
3. **权限回调与异步**：`ask_user` 是同步 input()，在异步 REPL 中需要用 `asyncio.to_thread` 包装
4. **Store 单例与并发**：当前 Store 是进程级单例，如果未来支持多会话需要重构
