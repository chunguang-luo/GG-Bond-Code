# 上下文管理 - 实现计划

> 基于原文档：`claude-code-docs/06-上下文管理.md`

## 文档核心要点总结

### 核心概念

1. **Token 预算管理**：三个关键函数定义上下文运行边界——`getEffectiveContextWindowSize()`（实际可用空间）、`getAutoCompactThreshold()`（自动压缩触发线）、`calculateTokenWarningState()`（四级告警体系）
2. **Microcompact**：最轻量的上下文清理，不调用模型，直接清理旧的工具调用结果释放空间。有两条路径——Time-based（cache 冷时直接替换内容）和 Cached Microcompact（cache 热时通过 `cache_edits` API 删除）
3. **API-level Context Management**：独立的并行机制，通过声明式策略委托 API 服务端执行上下文清理（清除 thinking、清除旧 tool results）
4. **Full Compact**：用模型总结整个对话。三种路径——Session Memory Compact（免 API 调用）、传统 Compact（模型生成 9 维结构化总结）、compact prompt 工程技巧（CoT 剥离、NO_TOOLS_PREAMBLE）
5. **FileStateCache**：追踪文件读写安全状态，核心语义是 `isPartialView`（截断注入标记），compact 后作为文件恢复索引
6. **Compact 后上下文重建**：清理文件缓存 + 并行恢复关键附件（最近文件、Plan、Skill），有严格 token 预算控制
7. **熔断器**：连续 3 次 compact 失败后停止尝试，避免浪费 API 调用
8. **postCompactCleanup**：清理多级缓存，区分主线程/子 Agent 避免状态损坏

### 关键设计模式

- **多级压力梯度响应**：低压 Time-based → 中压 Cached Microcompact → 高压 Full Compact → 极限 Blocking
- **熔断器 + 连续失败计数**：3 次连续失败后熔断
- **Chain-of-Thought 然后剥离**：`<analysis>` + `<summary>`，后处理剥离 `<analysis>`

**任务 5：熔断器（`compact/circuit_breaker.py`）**

```python
class CompactCircuitBreaker:
    """连续失败超过阈值后停止尝试 compact

    Claude Code 实践：3 次连续失败后熔断。
    统计显示有些 session 会连续失败数千次，每天浪费 25 万次 API 调用。
    """

    def __init__(self, max_failures: int = 3):
        self._max_failures = max_failures
        self._consecutive_failures = 0

    @property
    def is_open(self) -> bool:
        """熔断器是否打开（应停止尝试）"""
        return self._consecutive_failures >= self._max_failures

    def record_success(self) -> None:
        """记录成功，重置计数器"""
        self._consecutive_failures = 0

    def record_failure(self) -> None:
        """记录失败，递增计数器"""
        self._consecutive_failures += 1
```

**任务 6：重构策略接口（`compact/strategy.py`）**

当前 `CompactStrategy` 的 `should_compact` 接受 `current_tokens` 和 `max_tokens` 但 `MessageCountStrategy` 和 `TokenCountStrategy` 的实现过于简单。需要：

- 保留 `CompactStrategy` ABC 和 `repair_tool_references()` 不变
- 让 `MessageCountStrategy` 和 `TokenCountStrategy` 保持向后兼容
- 新增 `CompactLevel` 枚举表示压缩级别（MICRO / FULL / BLOCKING）
- 新增 `CompactManager` 统一管理多级压缩流程

```python
class CompactLevel(Enum):
    MICRO = "micro"       # 清理旧工具结果
    FULL = "full"         # 模型总结对话
    BLOCKING = "blocking" # 禁止新查询

class CompactManager:
    """统一管理多级压缩流程

    模仿 Claude Code 的压力梯度响应：
    1. 检查 token 用量
    2. 未达 micro 阈值 → 不压缩
    3. 达到 micro 阈值但未达 auto-compact → Microcompact
    4. 达到 auto-compact 阈值 → Full Compact
    5. 达到 blocking 阈值 → 禁止新查询
    """

    def __init__(self, model: str):
        self._model = model
        self._circuit_breaker = CompactCircuitBreaker()
        self._micro = MicrocompactStrategy()
        self._full = FullCompactStrategy()

    def evaluate(self, token_usage: int) -> tuple[CompactLevel, TokenWarningState]:
        """评估当前需要什么级别的压缩"""

    async def execute(
        self,
        level: CompactLevel,
        messages: list[dict],
    ) -> tuple[list[dict], str]:
        """执行指定级别的压缩"""
```

```python
from dataclasses import dataclass
from collections import OrderedDict

@dataclass
class FileState:
    """文件读取状态条目"""
    content: str                # 原始磁盘内容（用于 diff 比对）
    timestamp: float            # 读取时间
    offset: int | None = None   # 读取偏移
    limit: int | None = None    # 读取行数限制
    is_partial_view: bool = False  # 是否为截断注入的内容

class FileStateCache:
    """文件读写安全状态追踪

    核心职责：
    1. 追踪文件的读取状态与可编辑性
    2. isPartialView 标记：截断注入的文件内容不可直接编辑
    3. Compact 后作为文件恢复索引
    """

    def __init__(self, max_entries: int = 100, max_size_bytes: int = 25 * 1024 * 1024):
        self._cache: OrderedDict[str, FileState] = OrderedDict()
        self._max_entries = max_entries
        self._max_size_bytes = max_size_bytes
        self._current_size = 0

    def get(self, path: str) -> FileState | None:
        """获取文件的读取状态"""

    def set(self, path: str, state: FileState) -> None:
        """记录文件的读取状态"""

    def can_edit(self, path: str) -> bool:
        """检查文件是否可以安全编辑（非 partial view）"""

    def clear(self) -> None:
        """清除所有缓存（compact 后调用）"""

    def get_recent(self, n: int = 5) -> list[tuple[str, FileState]]:
        """获取最近读取的 N 个文件（按时间戳排序，compact 后恢复用）"""

    def clone(self) -> FileStateCache:
        """克隆缓存（sub-agent 隔离用）"""
```

**任务 13：postCompactCleanup（`compact/cleanup.py`）**

```python
def run_post_compact_cleanup(
    query_source: str | None = None,
) -> None:
    """Compact 后清理多级缓存

    区分主线程/子 Agent：
    - 子 Agent 和主线程共享模块级状态
    - 子 Agent compact 时不应清理主线程的缓存
    """

    # 始终清理
    reset_microcompact_state()
    clear_system_context_cache()

    # 仅主线程清理
    is_main_thread = (
        query_source is None
```

## 风险评估

### 架构风险

| 风险 | 影响 | 缓解策略 |
|------|------|---------|
| Full Compact 依赖模型 API 调用，增加延迟 | 🟡 中 | 优先使用 Microcompact；Session Memory Compact 免调用；熔断器防止浪费 |
| 多级压缩增加 QueryRunner 复杂度 | 🟡 中 | CompactManager 封装决策逻辑，QueryRunner 仅调用 evaluate + execute |
| FileStateCache 引入新的内存开销 | 🟢 低 | 双重限制（max entries + max size），LRU 淘汰 |

### 性能风险

| 风险 | 影响 | 缓解策略 |
|------|------|---------|
| Token 计算开销（估算每条消息 token 数） | 🟡 中 | 使用近似估算（字符数/4），避免每条消息都调用 tokenizer |
| Full Compact 增加 API 调用 | 🟡 中 | 熔断器 + 优先 Microcompact + Session Memory Compact 免调用 |

### 向后兼容风险

| 风险 | 影响 | 缓解策略 |
|------|------|---------|
| 修改 `CompactStrategy` 接口 | 🟡 中 | 保留现有 `MessageCountStrategy` / `TokenCountStrategy` 不变，新增 `CompactManager` |
| 修改 `/compact` 命令行为 | 🟢 低 | 新行为更优（模型总结 vs 简单截断），用户可感知提升 |

## 可迁移的设计模式

### 模式 1：多级压力梯度响应

- **类别**：行为模式
- **描述**：设计从轻量到重量级的干预措施，在不同压力等级触发不同响应
- **适用场景**：任何有资源限制的系统——内存管理、数据库连接池、API 配额
- **Python 实现**：
```python
class PressureLevel(Enum):
    LOW = "low"       # 轻量清理
    MEDIUM = "medium" # 中等压缩
    HIGH = "high"     # 重量级压缩
    CRITICAL = "critical"  # 禁止新请求

class PressureGradientManager:
    def evaluate(self, usage: float, limits: dict[PressureLevel, float]) -> PressureLevel:
        for level in [PressureLevel.CRITICAL, PressureLevel.HIGH, PressureLevel.MEDIUM, PressureLevel.LOW]:
            if usage >= limits[level]:
                return level
        return PressureLevel.LOW
```

### 模式 2：熔断器 + 连续失败计数

- **类别**：行为模式
- **描述**：连续失败超过阈值后停止重试
- **适用场景**：API 调用、数据库重连、任务队列
- **Python 实现**：
```python
class CircuitBreaker:
    def __init__(self, max_failures: int = 3):
        self._max_failures = max_failures
        self._consecutive_failures = 0

    @property
    def is_open(self) -> bool:
        return self._consecutive_failures >= self._max_failures

    def record_success(self) -> None:
        self._consecutive_failures = 0

    def record_failure(self) -> None:
        self._consecutive_failures += 1
```

### 模式 3：Chain-of-Thought 然后剥离

- **类别**：实现模式
- **描述**：让模型在 `<analysis>` 中推理，后处理剥离，只保留 `<summary>`
- **适用场景**：任何需要高质量摘要/总结的场景
- **Python 实现**：
```python
import re

def format_with_cot_stripping(raw_output: str) -> str:
    # 剥离 <analysis>...</analysis>
    result = re.sub(r'<analysis>[\s\S]*?</analysis>', '', raw_output)
    # 提取 <summary>...</summary>
    match = re.search(r'<summary>([\s\S]*?)</summary>', result)
    if match:
        return match.group(1).strip()
    return result.strip()
```
